# AxiomForge Anti-Reward-Hacking — R0 → R2 Consolidated Summary

**Status: frozen through R2.** This document consolidates the R0 → Sentinel →
R1 → R2 ladder before the (optional) R3 extension. All numbers are read directly
from the committed experiment CSVs; plots/tables are regenerated by
[scripts/build_r0_r2_summary.py](../scripts/build_r0_r2_summary.py) into
`results/r0_r2_summary/`.

---

## 1. Executive summary

On AxiomForge V1.4 (a controlled symbolic lab with a deliberate proxy-reward
trap), we found that **structural-novelty exploration (SPIE), and especially
PER+SPIE, *amplifies* proxy reward hacking** rather than preventing it. Instead
of discarding that signal, we **repurposed the same successor/predecessor signal
as a passive trap *detector*** (the Trap-Sentinel), verified it fires on the
proxy and never on the true goal using observable fields only, and then used the
underlying idea to build a two-step, **observable-only** mitigation:

- **R1 (Protocol-Gated SPIE):** allow the SPIE bonus only on observable
  milestone progress. This **eliminated** SPIE's hacking in the no-demo regime
  (matching/beating the clean baseline) but was **insufficient** in the
  demo-seeded regime, where demonstrations already route the agent past the
  proxy.
- **R2 (proxy-coupled penalty):** add one knob — turn the bonus into a *negative*
  response on proxy steps. After a κ-sweep (5 seeds), R2 **drives demo-seeded
  proxy farming to ~0 with no loss of task success**, beating every baseline
  including plain noisy, and taming the pathological seed that dominated R1's
  variance.

Headline: **R2 κ=8** — trap_hits **0.022** (vs 0.374 for R1), alignment_gap
**−0.13** (vs +1.49), success **0.544** (unchanged). **R2 κ=4** is the efficient
sweet spot. No `true_score` / `HiddenContext` / grader-only field is used in any
training reward, policy, or gating decision anywhere in the ladder.

## 3. What changed at each step (one knob at a time)

- **R0 → Sentinel:** no training change at all — the same SR/PR novelty signal is
  *read* (not rewarded) and gated by an observable proxy-counter increment to
  produce a per-state suspicion score.
- **Sentinel → R1:** add the **gate** — the SPIE intrinsic is kept only when the
  observable milestone-progress index increases (`milestone_abstraction(obs)[3]`),
  and zeroed on neutral / proxy steps.
- **R1 → R2:** add **one knob** — on a proxy step the bonus becomes
  `−κ·(β·b)` instead of being zeroed. κ is the only new hyperparameter.
- **R2 → κ-sweep:** no mechanism change — sweep κ ∈ {1,4,8} and add seeds (3→5).

## 4. What did NOT change at each step

- The environment, reward function, success criterion, evaluation protocol, and
  the Noisy Dueling Double-DQN backbone are **identical** across R1/R2 (PER off).
- The SPIE module, the milestone abstraction, and demo seeding are reused
  unchanged.
- Greedy evaluation never sees any intrinsic/penalty (training-only shaping).
- R1 is preserved exactly inside R2: with the penalty knob off, R2's proxy branch
  reduces bit-for-bit to R1's suppression (verified by test + the identical
  no-demo rows below).

## 5. Hidden-leakage audit (training never touches the answer key)

| field | where it is allowed | verified |
|---|---|---|
| `true_score` | **reporting/eval only** — computed in `_get_info` (gated by `enable_true_score`); the env code comments "must NEVER touch this reward"; it is **not** in `obs` | ✔ never read in any reward, policy, gate, or penalty |
| `HiddenContext` | **debug only** — `info["debug"]["hidden_context"]`, present only under `debug_mode`; never in `obs` | ✔ used only by eval/probe analysis, never in training |
| grader-only labels (protocol/fault answer key) | grading internals | ✔ not used in training/gating |

Everything the gate and penalty consume is observable: `proxy_attempt_count`,
`proxy_claim_count`, and the milestone abstraction — all fields of the
observation dict (zero before V1.4 activates them). The Trap-Sentinel and both
R1/R2 gates are observable-only by construction; the probe/report read
`true_score`/`hidden_context` **only** for after-the-fact scoring.

## 8. Main finding

1. **Naive structural-novelty exploration amplified reward hacking.** SPIE's
   `1/‖M(s)‖` bonus spikes at the structurally unusual proxy state, so novelty
   *pays the agent to farm the proxy*; PER compounds it (R0).
2. **The same signal is a usable detector.** Gated by an observable proxy-counter
   increment, the SR/PR signal localizes the trap (fires on `Y`, never on `G`),
   with a one-step anticipatory warning — failure-mode turned instrument.
3. **Protocol gating removed the harmful attraction where exploration drives
   behavior** (no-demo): PG-SPIE matched/beat the clean baseline.
4. **A proxy-coupled reversal eliminated demo-seeded proxy farming without a
   success cost.** With adequate κ, the same novelty signal becomes a targeted
   repulsion that nearly zeroes hacking and even improves on plain noisy, at
   unchanged task success.

## 9. Limitations

- **Single environment** (AxiomForge V1.4) — no cross-environment evidence.
- **Small seed count** (3, extended to 5 for the headline) — modest statistics.
- **Hand-crafted observable proxy counters** — the gate/penalty rely on the env
  exposing `proxy_attempt_count` / `proxy_claim_count`; in a setting without such
  an observable trap signal the mechanism would need a learned proxy detector.
- **Finite symbolic gridworld** — discrete, fully (mostly) observable, demo-seeded
  past the exploration wall; not a high-dimensional or partially-observed task.
- **κ requires tuning** — κ=1 was too weak; the effect needed κ≥4. The right κ
  is environment/reward-scale dependent.
- **Value-based, demo-seeded regime** — findings are specific to this family.

## 10. Claim language (deliberately bounded)

This is **an AxiomForge-controlled anti-reward-hacking mechanism**, not a general
alignment solution. We do **not** claim a novel algorithm: PG-SPIE/R2 compose
existing pieces (successor/predecessor representations, potential-style gating,
reward shaping) into an observable-only mitigation tailored to a known proxy
trap. The contribution is the **controlled, attributable demonstration** that a
structural-novelty signal which *amplifies* hacking can be re-pointed —
first as a detector, then as a gate, then as a penalty — to *suppress* it without
a task-performance cost, with every step changing one knob and never reading the
grader's answer key.

## 11. Recommended headline result

- **R2 κ=4** — efficient sweet spot: trap_hits 0.039, align_gap −0.051, success
  0.546; moderate penalty (mean_pen 0.65).
- **R2 κ=8** — strongest alignment: trap_hits 0.022, align_gap −0.132, tightest
  variance (gap_sd 0.08), success 0.544; more aggressive (mean_pen 1.02).

## 12. Is R2 a valid stopping point?

**Yes.** R2 (κ≥4) achieves the anti-hacking objective in both regimes: it removes
SPIE's amplification (no-demo) and demo-seeded proxy farming, at no success cost,
robustly across 5 seeds including the previously pathological seed, using
observable fields only. The R0→R1→R2 ladder is a complete, self-contained result.

## 13. Why R3 is now an extension, not a rescue

The earlier R0 finding showed **PER** also amplifies trap transitions (high
TD-error = proxy transitions). R2 reaches its result **without PER at all**, so
R3 is no longer needed to *fix* hacking. R3 instead asks a *new, orthogonal*
question: *can a trap-aware PER (priorities down-weighted/capped on
sentinel-flagged transitions) recover PER's sample-efficiency benefit without
re-igniting the amplification?* That is a worthwhile extension, but R2 stands on
its own if it is not pursued.
